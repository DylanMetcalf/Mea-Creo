# Database

PostgreSQL 16 through Drizzle ORM. **Status:** planned; the schema lands in Phase 2.
This document is the agreed design and is updated as tables are created.

## Conventions

- **Ids:** UUIDv7 (time-ordered, safe to expose). External system ids go in
  `external_id` plus `external_provider` columns.
- **Timestamps:** `created_at`, `updated_at` (`timestamptz`, UTC). Display time zone
  defaults to `Africa/Johannesburg`, per organisation.
- **Tenancy:** tenant tables carry `organisation_id` (not null, indexed, FK). Repositories
  require a `TenantContext`; RLS policies enforce `organisation_id = current_setting('app.organisation_id')`.
- **Money:** `amount_minor bigint` plus `currency char(3)`. Never floats.
- **Status fields:** Postgres enums or `text` with check constraints mirroring TypeScript unions.
- **Soft delete:** `archived_at` for business records (clients, documents, services).
  Hard delete only through the retention and deletion workflow.
- **Visibility:** `visibility` (`internal` | `client`) on records a client might see
  (notes, documents, tasks, timeline entries, reports).
- **Provenance** on Client Brain facts and AI output: `source_type`
  (`human` | `import` | `integration` | `agent`), `source_ref`, `verification`
  (`verified` | `unverified` | `rejected`).
- **Files:** only metadata and the object key. Binaries live in object storage.
- **Migrations:** generated by drizzle-kit, reviewed, committed as SQL, applied by
  `pnpm db:migrate` in CI/CD before the new release serves traffic. Additive first; destructive
  changes happen in a later release (expand, then contract).

## Entities (planned)

Identity and tenancy
: `organisations` (kind: `platform` | `client`), `users`, `memberships` (user, org, role),
`roles`, `permissions`, `role_permissions`, `invitations`, `sessions`, `accounts` (OAuth),
`verification_tokens`, `client_assignments` (staff user to client org, with responsibility)

Clients and intelligence
: `clients` (profile, health, owner, billing state), `contacts`, `client_brain_facts`,
`client_goals`, `client_kpis`, `competitors`, `brand_assets`, `timeline_entries`

CRM and acquisition
: `companies`, `prospects`, `deals` (funnel stage), `activities`, `notes`,
`prospect_scores` (per dimension with reasons), `consents`, `utm_touches`

Audits
: `audits` (url, status, requested_by), `audit_findings` (category, status, finding,
why it matters, recommendation), `audit_opportunities`

Services and commercial
: `services`, `service_deliverables`, `packages`, `package_items`, `price_books`,
`prices` (per currency), `tax_rates`, `client_services` (active, paused, cancelled),
`service_requests`, `proposals`, `proposal_items`, `proposal_acceptances`

Billing
: `subscriptions`, `invoices`, `invoice_lines`, `payments`, `payment_events` (raw webhooks,
idempotent on the provider event id), `billing_state_changes`

Work
: `projects`, `tasks`, `task_dependencies`, `recurring_task_templates`, `approvals`,
`approval_decisions`, `comments`, `meetings`, `meeting_briefs`, `meeting_notes`

Documents and content
: `documents`, `document_versions`, `document_tags`, `content_items`, `case_studies`,
`insights`, `portfolio_items`, `knowledge_articles` (SOPs, methodology)

Reporting and analytics
: `reports`, `report_sections`, `search_metrics_daily`, `analytics_metrics_daily`
(kept separate), `kpi_snapshots`

Automation and AI
: `domain_events` (outbox), `workflows`, `workflow_rules`, `workflow_runs`,
`workflow_steps`, `agents`, `agent_permissions`, `prompt_versions`, `agent_runs`,
`agent_outputs`, `ai_usage` (model, tokens, cost, client, agent, workflow), `budgets`

Platform
: `integrations` (per org, encrypted credentials, status), `integration_sync_runs`,
`notifications`, `notification_preferences`, `activity_log` (who, what, when, old and
new values, source, reason), `settings` (per org, typed JSON with schema version),
`feature_flag_overrides`, `emergency_controls`, `redirects`

## Backups

Managed Postgres with daily snapshots and point-in-time recovery (at least 7 days; 30 days
recommended). Weekly logical dump (`pg_dump`) to separate object storage in another
region. Restores are tested quarterly. See DEPLOYMENT.md for the procedure.
